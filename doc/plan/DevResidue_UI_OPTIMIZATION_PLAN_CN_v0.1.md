### 1.2 不可改变的约束

1. Provider、Kondo、AI 不执行删除；CleanupEngine 是唯一删除 authority。
2. 清理请求只能传 ScanItemId / CleanupPlanId 与既有授权参数，不新增 deletePath、runCommand、任意路径删除接口。
3. UNKNOWN、PROTECTED 不因界面改版、全选、AI 建议、最高确认策略而自动获得删除资格。
4. 不削弱 Reparse、TOCTOU、进程状态、规则、计划完整性与 generation 校验。
5. Core 不依赖 React、Tauri 或 WebView。新增展示元数据不参与授权推导。
6. 保留现有真实 / 演示适配器边界；演示成功不得冒充真实后端能力。
7. API Key 不进入 Zustand、localStorage、日志、截图、测试快照；沿用现有安全保存通路。
8. 不执行 Git 写操作。需要用户保存提交、切换分支或恢复版本时，由用户自行操作。
9. 默认复用现有依赖。新增 / 升级依赖、修改依赖清单须遵守项目审批规则；不得为方便 UI 重构自行安装组件库或测试框架。
10. 本计划不包含品牌重做、移动端、云同步、自动清理、自动采纳 AI、真实磁盘占用测量、回收站 / 撤销能力新增。

## 4. B01：修复清理语义、风险摘要与过程反馈

### 现状与目标

F01 已复现：22.2 GiB npm cache 在允许重新下载后，最终确认错误显示“仅包含低风险候选”。F02：永久删除语义在步骤间不连续。F08：planning / dry-run 已有状态但无对应视图。

主要文件：src/components/CleanupFlow.tsx、src/stores/cleanupStore.ts、src/stores/generationLifecycle.ts、src/utils/format.ts。建议新增 src/utils/cleanupPresentation.ts；必要时拆出 src/components/cleanup/ 下组件。

### 子任务

**B01.1 建立统一展示函数。** 将 actionLabel、确认要求、跳过 / 失败原因摘要从 CleanupFlow 提取到纯函数。输入保留原始枚举，输出中文名称、简述与原始详情。计划、预演、最终结果、记录页都复用；不改变 wire 枚举。核对 WindowsDeletePort 的实际行为，当前 recycle / delete 不得描述成可从回收站恢复。外部工具显示“执行工具清理”，未知动作显示“未识别操作”并可查看原值。

**B01.2 将风险与授权分开。** 依据当前计划条目的 confirmation 汇总 redownload / review 数量，并结合本次 generation 的 ScanItem 风险区分 safe / regenerable-local；不要使用 policy 决定风险提示是否存在。授权策略只控制授权状态和既有门禁。缺失匹配条目、generation 不一致时要求重新生成计划，不猜测为低风险。

展示必须包括：对象数量、逻辑大小估计、永久删除 / 工具清理数量、重新下载 / 本地重建 / 可能失去历史的影响。混合计划分组显示。confirmation=none 改为“无需额外风险授权”。“低风险候选”只用于适用集合，不能保证零影响。

**B01.3 重整最终确认。** 仅阅读最后一步也应能知道处理对象与后果。纯直接删除按钮为“永久删除 N 项”；纯工具计划为“执行工具清理”；混合计划为“执行清理（N 项）”，紧邻列明各动作数量。取消为初始焦点。不要新增默认勾选授权，不自动提升 policy，不提供虚假撤销。

**B01.4 保持复核容器稳定。** planning、plan-review、dry-run、dry-run-review 使用同一个复核外框：摘要始终保留，中央区域在计划表与预演结果间切换。预演明确“未删除文件”；工具查询等既有只读验证仍可能执行，不写“没有发生任何操作”。忙碌时显示真实阶段与不定进度，不估造百分比、ETA。预演后最后确认仍单独进行。

**B01.5 防止异步结果回写失效流程。** cleanupStore 为请求保存递增 request token、generation、planId。执行前关闭、替换计划、新扫描或重置使旧计划 / 预演响应失效；晚到的成功和失败都不能重新打开旧复核弹窗。选择集合或 policy 改变后必须重新生成计划 / 预演，不复用旧确认。重复点击不得重复调用执行。planning / dry-run 期间不能重复提交；如果后端没有取消能力，就明确等待，不能把关闭界面写成已取消执行。

真实 executing 是单独边界：不可被 Escape / 背景点击或普通 close() 清掉。执行一旦开始，保留绑定原 generation / planId 的运行与结果记录；即使外部扫描使当前 generation 变化，也不能丢弃该执行终态并误报未执行，而应说明这是原计划的结果、刷新记录并要求新的清理重新选择。新代次不能把该结果绑定到新条目；终态后可关闭。B03 再从后端阻止本应用同时启动冲突任务。

**B01.6 修正文案单位。** 删除“约 X GiB 的编译时间”“一定重新下载 X GiB”等表述。推荐“当前占用估计 X；下次使用需要本地重建 / 联网重新下载，耗时或流量取决于实际使用”。与证据不符的绝对“安全”统一成“低风险候选”；核心枚举保持 safe。

### 验证与完成标准

- UI-010：safe、local、download、review、混合计划均显示正确影响；default / redownload / review / all 不会把高恢复成本变成低风险。
- UI-011：不存在条目或旧 generation 的计划不能进入执行确认；UNKNOWN / PROTECTED 仍被后端拒绝。
- UI-012：计划 → 预演 → 确认 → 结果的动作称谓一致，取消不执行，重复点击只发送一次执行请求。
- UI-013：延迟 3 秒、失败、关闭后晚到、新扫描后晚到的响应，界面均不跳回旧计划；真实执行期间不得显示已取消。
- UI-014：四种计划状态截图可比对；最终确认单屏包含主要后果，长清单在内部滚动且按钮可见。
- 自动化：纯函数汇总表驱动用例、异步 store 探针、npm run build。纯文案无需逐句快照测试。

完成后 F01 关闭；F02 标“主流程已修复，待 B07 日志闭环”；F08 标“清理过程反馈已修复，扫描部分待 B06”。

## 5. B02：统一键盘、弹窗与页面语义

主要文件：src/components/ResultsTable.tsx、CleanupFlow.tsx、ScanBar.tsx、Sidebar.tsx、AiProfilePanel.tsx、src/pages/JournalPage.tsx、SettingsPage.tsx、src/components/AppShell.tsx。建议新增 src/components/common/ModalFrame.tsx。

### 子任务

**B02.1 修复行与控件键盘冲突。** 行级 Enter / Space 仅在 event.target === event.currentTarget 时打开详情。checkbox、button、link 内的键盘事件保留原生行为；不能通过全局 preventDefault 修补。保留复选框点击不触发打开详情。排序列保留可操作按钮及 aria-sort。

**B02.2 抽取共用 ModalFrame。** 以现有清理弹窗为基础，实现 role=dialog、aria-modal、标题关联、必要说明关联、焦点进入、Tab 环绕、Escape 条件关闭、关闭后返回触发元素。背景设置 inert 或等效实际不可聚焦机制，不能只加 aria-hidden。调用方指定 initialFocusRef；不要用混合选择器误把第一个危险按钮当自动焦点。触发元素已被卸载时，焦点回到当前页面标题或合理入口。

所有确认 / 错误 / 重置弹窗复用；同时只存在一个活动模态层。执行中 dismissible=false；不允许背景点击关闭危险确认；无可聚焦控件时外框可接收焦点。异步状态变化后只在必要时移动焦点，避免每次重渲染抢焦点。

**B02.3 补齐表单与导航语义。** AI 主开关、工作区、名称、地址、模型、Key 等使用可见 label + htmlFor；错误通过 aria-describedby 关联。导航用 aria-current=page；筛选按钮用 aria-pressed，只有完整实现方向键与 tabpanel 关系时才使用 ARIA tabs。页面一个 h1，主要工作区 main，导航 nav；图标按钮有名称。

**B02.4 统一状态反馈。** ScanBar 警告展开改原生 button，标注 aria-expanded 和 aria-controls。状态文本用 role=status / aria-live=polite；阻断错误用适度 alert。不要逐条扫描事件高频播报，合并阶段变化。忙碌区域 aria-busy，不能仅靠 spinner 表示。

**B02.5 验证共用规则。** 保留可见焦点。页面跳转、打开 / 返回详情、弹窗关闭后焦点位置可预测。完成一次仅键盘的“扫描结果 → 勾选 → 详情 → 计划 → 预演 → 取消确认”。后续新增组件必须沿用本批契约。

### 验收

- UI-020：复选框焦点下按 Space 只改变勾选；行焦点按 Enter 才打开详情；保护项无法被键盘勾选。
- UI-021：正反 Tab 不离开模态层；Escape 只关闭允许关闭的弹窗；危险按钮不默认获焦；关闭返回正确入口。
- UI-022：所有表单控件和图标按钮在可访问性树中有合理名称；导航与筛选可读出当前状态。
- UI-023：警告详情可完全通过键盘展开、关闭，动态错误不静默且不持续刷屏。
- 自动化：使用可用浏览器工具检查真实 DOM / 焦点；没有浏览器测试框架时记录可复现操作，不安装依赖来凑自动化覆盖。

本批不做整体配色重绘；对比度、强制颜色、减少动态效果在 B10 / B11 统一验证。

| 窗口 | 960×640 两列概览摘要；1200×900 常规布局；1440×900 检查宽屏密度 |

### 子任务

**B10.1 整理 tokens。** 抽取文字、背景、边框、语义色、间距、圆角、阴影、字号和层级变量。浅 / 深主题分别定义真实前景背景组合；组件只引用语义 token。找出 global.css 尾部同组件重复覆盖，随迁移删除已失效规则；每迁移一组验证关联页面，不大范围替换色值。

**B10.2 统一页面框架。** 所有页面使用一致页头、说明、工具栏、内容区；全局 ScanBar 与内容保留稳定边距。单个区域只有一个主要下一步。空态使用短标题、原因、可执行动作，不增加无用指标填白。整理概览大卡片与日志 / 规则密度差异，默认视图优先展示任务信息。

**B10.3 整理列表与详情。** 名称和路径分层，大小列不压缩到逐字折行；路径可截断但详情能查看 / 复制完整值。短动作与数值禁止逐字换行；说明文字自然换行，不强制撑宽。详情按 B08 顺序呈现；证据默认折叠；已选行有勾选识别，正在查看的行使用独立边线 / 背景，不能共用唯一颜色表达。

**B10.4 修复颜色与对比度。** 原浅色导航分组约 3.92:1，应修正到普通文字至少 4.5:1 的参考目标；逐一测量真实组合，不能仅校验 token 色值。检查浅 / 深下正文、辅助、按钮、徽标、选中行、焦点、边框。大文字参考 3:1；交互边界 / 图形根据用途检查，不能声称一个数字证明整个应用合规。保护态不再与失败 / 危险按钮混用红色。

**B10.5 响应式与环境偏好。** 960 宽四张成本卡片为 2×2，宽窗口可四列；表单在窄窗口单列；弹窗 max-height 随窗口，正文滚动而底部操作可见。适配长中文、长英文、200% 文本 / 显示缩放，不仅测试理想短数据。prefers-reduced-motion 减少非必要转场；forced-colors 保留系统颜色下的焦点、边界和状态文字，不依靠 box-shadow 单独呈现选中。

**B10.6 检查大列表密度和响应。** 在纯 Mock 下测试 1,000 / 10,000 条，记录过滤、排序、选择耗时与 DOM 行数。首先避免重复 selector 计算和 render 内全表扫描；需要限制 DOM 时使用无新依赖的分页，每页默认 100 条，清楚显示页码与结果总数。搜索 / 排序针对完整结果集；“全选当前筛选结果”明确作用于所有匹配项，不能被分页改成仅当页。项目分组不得因分页造成未说明的组统计截断。只有实测仍不足时再提出虚拟列表方案，不先安装依赖。

## 18. 变更控制与完成定义

1. 前置批次未达到入口条件时，不跳过依赖实施外观层来掩盖行为问题。
2. 当前代码已完成某个建议时，核对验收并记录复用，不再次替换实现。
3. 新发现的独立问题先记录到进度文档；只有阻断当前验收时纳入最小修复，避免把 UI 优化变成无限架构重构。
4. 更改本计划的分类、接口或流程决策时，必须记录原因、受影响批次和验收调整；不能让下一个模型从失真的计划继续。
5. 每批回退采用用户保存的检查点与该批修改清单。模型不能执行 Git reset / checkout / revert，也不能用覆盖文件清除用户工作。
6. 本轮最终完成须满足：全部建议有实现、全部必需验收有结果、P1 失败清零、缺少环境的验证被解决或由用户明确接受边界。验收报告必须与产品实际状态一致。

最先交给实施模型的任务是 B00.1；完成 B00 后从 B01.1 开始。不要以“完成全部优化”为一个不分阶段的执行请求。
